1. Stop two writers from clobbering each other
Today, saving a note works in two steps: look to see whether the note already exists, then insert or update it. If two agents save the same note in the same instant, the second one acts on a stale read and can throw away the first one's confidence bump or provenance. The fix is what Lamis described as the hash dance: give every note a version number. A writer reads the note and its version, decides what the new body should be, then writes only if the version hasn't moved. If it has moved, the write re-reads and tries again, a couple of times, then gives up loudly rather than silently losing data.
This is a narrow change to the save function and the retry path. Concurrency in this project is low (one CLI, one cron), so it's mostly insurance — but insurance that costs about ten lines.
