Collective memory for agent sessions

Memory that
sleeps on it.

mem gives a fleet of coding agents one SQLite ledger and one folder of markdown. During the day they write what they learn. At 03:00 a dreaming pass rereads the transcripts, checks what is still true, and stages what tomorrow’s agent should know.

01 / LOOP

One store,
two loops.

Real time is small. Agents write checkable notes while they work and recall them in the next session. Batch time is a different process with its own budget, its own visibility, and a diff you can reject.

Every note is one row in memory.db and one bullet in a markdown file such as memory/deploy.md. The ledger id rides along in an HTML comment, so the readable file and the database never drift apart. A single writer, recordNote, takes a per-file lock; a live edit and a nightly rewrite queue behind the same lock instead of overwriting each other.

Notes are scoped to this project + global, never another project’s memory. Each one carries a topic, a fingerprint, provenance, and a confidence. Usage decides survival: every recall records a hit, decay retires what nobody asks for, and promotion lifts a claim only after it is hit in two different projects.

Nothing destructive happens unattended. A verify rewrite or drop is staged and reviewed exactly like a dream run; splits, moves, cross-links, and enrichment can land automatically. revert RUN restores the previous note for every change the run made.

02 / USE

A day in
the store.

Five commands carry the real-time loop. The transcripts below are from a scratch run of this repository; paths are shortened, output is trimmed, and nothing is staged until the night.

STEP 01

Open the store. Start a session.

The first command in a new directory registers the project lazily. No patch to try is required.

STEP 02

Ask for it back. Watch the score.

Recall reads this project plus global, ranks by confidence, recency, and use, and records a hit for every note it returns.

memory/deploy.md · topic filemarkdown
# Deploy

<!-- generated by mem. write through
     `mem remember`, never by hand. -->

- <!-- mem {"id":1,"kind":"gotcha",
  "confidence":0.78,"provenance":"session
  s-1042","topic":"deploy","version":1} -->
  bin/setup needs a Redis instance on port
  6379; it exits 1 with ECONNREFUSED
  otherwise.
  - Repro: `bin/setup`
  - Seen: 5 of 9 sessions (s-1042)
The body has to be checkable. A path, a command, a version, a specific gotcha. “Be careful with migrations” is a failed note. The HTML comment is the join key: erase the database and the file still knows which note it is.
STEP 03

Stage the night. Read the diff. Commit it.

Stage writes proposals to staged and stops. Review is read-only. Apply is deterministic and leaves a revision behind.

03 / DREAM

The 03:00
pass.

Dreaming is not a bigger prompt. It is a batch job with its own budget, its own visibility, and one job: make the memory better before the next session opens.

The packet carries the undistilled sessions and the current topic files. An agent reads all of it and proposes candidates: an insert, a merge into an existing note, an update with a known correction, or a retire. stage writes those proposals as one run. review shows the operation, the note it targets, the evidence, and the prevalence. Only apply changes live memory.

Inside the pass

Clone first.
Then fan out.

The orchestrator never edits the input store. It copies the live database to $MEM_OUT, hands each subagent one session transcript, and collects their candidates into one run.

  1. 01
    Clone the live store. The copy is a normal SQLite file.
  2. 02
    One subagent per session, PARALLEL=4 by default.
  3. 03
    Subagents read and write the copy. They propose; they do not edit.
  4. 04
    Collect merges duplicates and attributes every candidate to a session.

verify

Stat every backticked path, read the version a claim names, re-run read-only commands. True claims keep their place and can gain confidence; false ones are rewritten or dropped, with the reason and a revision behind them.

mem dream verify [--execute]

organize

Split a topic that grew past --split-at, merge names that converged (deploy/deploys), move a claim to the subject it actually names, and cross-link related files.

mem dream organize --split-at 20

enrich

Add what the transcripts taught: the reproducing command, prevalence (“3 of 12 sessions”), and the sessions that showed it. This is the part that turns prose into evidence.

mem dream enrich --since …
What waits for review? A verify rewrite or drop — anything that removes or replaces a claim. Splits, moves, cross-links, and enrichment land automatically. --auto runs enrich, organize, and verify for every active project, then promotes, decays, and archives untouched directories after 30 days. It never applies a destructive verify unattended.

Fan-out nights

One agent is
not a fleet.

scripts/dream.sh forks the live store, writes one transcript per undistilled session, and runs one agent per transcript in parallel. Agents propose candidates only; they never edit notes. collect merges duplicates, drops a stale update when a later session proposes a newer one, and attributes every candidate to a session.

Apply and reject both delete $MEM_OUT. A night that goes wrong is one deleted file away from never having happened. 

# 1 · copy the store, keep the live one untouched
$ mem dream fork --path
/tmp/mem-fork-8f2c.db

# 2 · one transcript per undistilled session
$ mem dream transcripts --dir .scratch/dream/transcripts \
    --since 2026-11-09T00:00:00Z

# 3 · one agent per transcript, PARALLEL=4
$ MEM_AGENT=./agent mem dream propose --db "$MEM_OUT" \
    --session s-1042 .scratch/dream/candidates/s-1042.json

# 4 · merge, dedupe, attribute, then stage as one run
$ mem dream collect "$MEM_OUT"
$ mem dream review 7
04 / CHARTS

What survives
the night.

Two mechanics do most of the work: a recall score that lets use beat confidence, and a decay curve that retires what nobody asks for. Both use the constants in src/notes.js.

Decay · 45-day half-life confidence · no recall hits
note at 0.92 note at 0.74 note at 0.66 retirement threshold

A note nobody recalls is gone in about six months.

mem decay sets confidence to min(confidence, confidence × 2−age/45) and retires anything below 0.05. A hit does not raise confidence directly; it lifts the recall score and keeps the note in front of agents, which is how it gets used again.

The top note falls from 0.92 to 0.05 in 189 days. The 0.74 note takes 175 days. One `decay` pass is a single night; these lines are the long-run shape.

AGE IS DAYS SINCE updated_at. use_count IS NOT PART OF DECAY; IT ONLY LIFTS THE RECALL SCORE.

Recall · one scratch project score · after one recall + one run
recall score confidence

Hits separate the score from the confidence.

After one recall and one dream run, the ledger ranks a 0.92 gotcha above a 0.84 convention: the gotcha has been retrieved and used, so its score is 1.56, not 0.92. The 0.74 migration note has no hits yet — its score is exactly its confidence.

That is the whole trick. Survival is not a property of the prose; it is a property of being asked for.

05 / INSIDE

Small enough
to read.

No service, no vector database, no runtime dependencies. Node’s built-in SQLite, five FTS triggers, and a single file plus its WAL siblings. Point MEMORY_DB anywhere and move on.

projectsOne row per try directory, registered lazily on the first session or note.
notesThe memory itself: scoped, topic’d, fingerprint-deduped, versioned.
note_hitsEvery recall and use, with weight. Drives decay and cross-project promotion.
sessionsOne row per agent session, carrying its diary and distill state.
dream_runsThe audit log of every night: counts, timestamps, source fork.
stagedProposals waiting for review; applied as deterministic operations.
run_sessionsWhich sessions a run was distilled from — the provenance of a night.
note_revisionsThe previous self of every note that was updated, promoted, or reverted.

The day

mem remember --topic --kind
Write a note through the lock; keep its id in the markdown file.
mem recall [--query] [--limit]
Rank this project + global and record a hit for each note returned.
mem topics · mem sync
List subject files, or rebuild them and the index from the ledger.
mem session start|end|diary
Open a session, attach a diary, distill it at night.

The night

mem dream --packet --since
Export undistilled sessions and current topic files as one packet.
mem dream stage FILE
Create a run and stage its proposals. Live memory is untouched.
mem dream review RUN
Print the diff: target, before/after, evidence, prevalence.
mem dream apply|reject|revert
Commit the run, throw it away, or restore every previous note.
mem dream --auto
Run verbs + promote, decay, archive. Destructive verify waits.

The fleet

mem dream fork --path
Copy the live store to a throwaway $MEM_OUT.
mem dream transcripts
Write one transcript per undistilled session.
mem dream propose
One agent, one session, candidates only — never note edits.
mem dream collect MEM_OUT
Merge duplicates, drop stale updates, attribute, stage one run.

The upkeep

mem dream verify|organize|enrich
The three verbs, each runnable on its own.
mem promote
Lift a claim hit in two different projects to global.
mem decay
Lower unused confidence; retire below 0.05.
mem revisions --note ID
Show what a note said before each update, promote, or revert.
